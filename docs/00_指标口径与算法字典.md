## 十六、⑤ 时序相似性聚类（N-Gram/DTW）——规格定义（2026-09-02）

**原理**：设备的下单行为构成可编码的"序列"，序列的相似性 = 行为指纹。换 IP/账号/设备后只要行为习惯不变，指纹就能重新关联到同一团伙。

**四条指纹序列**（基于 detail 明细，按 create_time 排序）：

| 序列 | 编码 | 相似度算法 | 捕捉什么 |
|------|------|-----------|---------|
| 航线序列 | N-Gram 二元组 | Jaccard | 行程路线依赖 |
| 金额档位序列 | 50 元档 N-Gram | Jaccard | 定价习惯（档位聚集的行为版） |
| 时间间隔序列 | 间隔秒值序列 | DTW | 下单节奏（对拉伸/压缩鲁棒） |
| 行为链序列 | 事件三字母编码（C=下单 P=支付 R=退款） | N-Gram | 操作流程习惯 |

**N-Gram**：把序列切成长度 N 的滑动窗口片段，两设备的片段集合做 Jaccard 相似度（交集/并集）。例：航线 [深圳→上海, 上海→北京, 北京→成都] 的二元组 = {(深圳→上海,上海→北京), (上海→北京,北京→成都)}。

**DTW（动态时间规整）**：允许序列在时间轴上弹性对齐后计算距离——两设备一个每天 10 单、一个每周集中 70 单，节奏"形状"相同则 DTW 距离小。适合比对下单间隔模式。

**聚类**：相似度矩阵 → 层次聚类（同社区内设备互比）→ "指纹团伙"分组，输出进前端设备明细徽章。

**增强字段口径**（02 SQL 已更新，ticket_dim 新增 7 列）：

| 字段 | 来源 | 含义 |
|------|------|------|
| flight_nums | s_flight_num 去重数组 | 航班级指纹（同航班反复订=强团伙信号） |
| dep_dates / dep_times | s_dep_date / s_dep_time | 行程节奏与时刻偏好 |
| cabins | s_cabin 去重数组 | 舱位偏好指纹 |
| ticket_status | p_ticket_status (MAX) | 票状态（出行/退票结局，骗赔方向） |
| passenger_genders / passenger_birthdays | p_gender / p_birthday | 乘机人结构指纹（证件池特征） |

## 十七、⑥ 演化检测（跨周期变形）——规格定义（待跨周期数据）

**输入**：上一周期（T-180d~T-90d）base+detail 各一份（同现有 SQL，改 START=90/END=180 导出，文件名 XX.XX.XX_base/detail.csv）。

**方法**：上/本周期团伙间计算两组距离——

#### 17.1 实体重叠度（entity_jaccard）完整公式

**实体集合构建**（每个设备 -> 实体集合，来自 detail 明细逐单累积）：
```
设备实体集 = { "ip:" + ip } ∪ { "card:" + 证件号 } ∪ { "mob:" + 手机号 } ∪ { "uid:" + user_id }
（去重；user_id 为空不计）
团伙实体集 E_gang = ∪ 成员设备的实体集
```
**公式**：`entity_jaccard(P团伙, C团伙) = |E_P ∩ E_C| / |E_P ∪ E_C|`
- 取值 0~1：1 = 两团伙用了完全相同的 IP/证件/手机/账号池，0 = 无任何共享实体
- 数据口径：P 团伙用 26.05.29_detail（上周期），C 团伙用 26.08.27_detail（本周期）
- 性能保护：任一集合 > 5000 实体时记 0（防热点实体膨胀拖垮计算）

#### 17.2 指纹相似度（fp_similarity）完整公式

**设备行为指纹**（三元组，按 create_time 排序的订单序列）：
```
指纹 = ( 航线bigram集, 金额档集, 航班号集 )
  航线bigram = 相邻两单航线二元组，如 (深圳>上海, 上海>北京)
  金额档    = order_amount / 50 四舍五入取整（50 元档位）
  航班号    = flight_nums 数组去重（航班级指纹）
团伙指纹 = ∪ 成员设备指纹（并集）
```
**公式**（团伙级加权 Jaccard）：
```
fp_similarity = 0.4 × Jaccard(航线bigram_P, 航线bigram_C)
              + 0.2 × Jaccard(金额档_P, 金额档_C)
              + 0.4 × Jaccard(航班号_P, 航班号_C)
```
- 航班号与航线 bigram 权重高（0.4）：行程路线是最难模仿的行为指纹
- 金额档权重低（0.2）：档位可选择的余地小、易撞车，只做辅助
- 取值 0~1，>= 0.25（TH_FP）判定为"指纹相似"

#### 17.3 形态判定阈值（[TUNABLE]）
```
hi_ent = entity_jaccard >= 0.15 OR dev_survive_ratio >= 0.3   （实体延续）
hi_fp  = fp_similarity  >= 0.25                                 （习惯延续）
组合成四形态（见下表）；dev_survive_ratio = |P设备∩C设备| / |P设备|（设备直接存活率）
```

**四种演化形态**：

| 实体重叠 | 指纹相似 | 判定 |
|---------|---------|------|

## 二十、①指纹团伙发现（2026-09-03，10 notebook）

### 20.1 航线团伙「套利率」（arb_device_ratio）完整口径

**数据链路（三层）**：

| 层 | 计算 | 代码位置 |
|----|------|---------|
| ①订单级：套利单判定 | `_arb_order = 全额退 AND 快退`。全额退 = \|refund_amount\| >= order_amount × 0.95（退掉的金额接近或等于支付金额）；快退 = 0 <= (refund_apply_time - pay_time) <= 3600 秒（支付后 1 小时内申请退款，[TUNABLE] 阈值 3600s，比短时退款的 600s 宽——套利追求快速回款） | 06 notebook cell3 |
| ②设备级：套利嫌疑设备 | `tag_arb = (arb_fast_full_cnt >= 2) OR (arb_full_refund_ratio >= 0.5 AND arb_has_refund >= 5)`。即：全额退+快退的套利单 >= 2 单（屡犯）；或全额退占设备总单 >= 50% 且有退款行为 >= 5 单（系统性） | 06 notebook cell6 |
| ③团伙级：套利率 | `arb_device_ratio = 套利嫌疑设备数 / 航线团伙设备总数`（分母=该航线团伙全部设备，含未入实体图的） | 07 notebook cell4 |

**原理**：骗赔套利的成本结构决定了"必须快速全额回款"——正常旅客极少在支付后 1 小时内退掉 95% 以上金额，更不会反复这么干。团伙级比率衡量这个航线团伙中"职业套利者"的密度。

**用途**：>= 30% 时该航线团伙被判为高置信团伙（双图融合的 OR 条件之一，另一条是与实体社区对齐 >= 40%）——含义是"这伙设备即使实体上不关联，行为上都是套利者"。

**注意**：refund_amount 是 COALESCE(支付表, 结算表) 双源（v4.2 起）；无赔付设备 comp 为空不计入。

- 指纹元素：航线一元+二元 + 金额档 + 航班号（>=4 元素的有效指纹设备 21,077 台）
- MinHash 128 位签名 + LSH（band=32/r=4 高召回，候选 7.6K 对）→ 精确 Jaccard >=0.30 过滤 → 连通分量
- 产出 130 个指纹团伙，其中 **13 个跨实体社区**（换马甲嫌疑）：F25 横跨 5 社区（14 台/1811 单）为最典型
- 设备徽章：「跨社区指纹」（橙）
